TASK 4 — BUILD THE CORE RULE ENGINE

Write: app/services/rule_engine.py

This is the heart of the V1 recommendation system.
Takes user context and returns a ranked list of meals.

Main function:

async def get_next_meal_recommendation(
    db,
    user_id: UUID,
    meal_type: str,  ← breakfast/lunch/dinner/snack
    flare_active: bool = False,
    limit: int = 5
) -> RecommendationResult

RecommendationResult dataclass:
  primary_recommendation: Meal
  alternatives: list[Meal]  ← next 4 best meals
  explanation: str           ← why this was recommended
  rule_applied: str          ← dominant rule priority
  flare_mode_active: bool
  nutrition_context: DailyNutritionState
  gaps: NutritionGaps

RULE ENGINE STEPS — execute in this exact order:

STEP 1 — Load candidate meals
  Query static.meals filtered by meal_type
  Load all matching meals with ingredients
  Start with full pool of candidates

STEP 2 — Apply safety filter (Priority 1)
  Load user allergies from core.user_preferences
  Remove any meal containing an allergen food
  These removals are HARD — never overridden
  Log each removal: [SAFETY: removed {meal} 
  due to allergy {allergen}]

STEP 3 — Apply medication filter (Priority 2)
  Call medication_filter.apply_medication_filter()
  Adjust scores based on medication rules
  Log applied rules

STEP 4 — Apply flare state reordering (Priority 3)
  If flare_active = True:
    REORDER — do not remove non-flare meals
    Put is_flare_friendly = true meals FIRST
    ordered by anti_inflammatory_score DESC
    Then append remaining meals below
    ordered by anti_inflammatory_score DESC
    
    This means:
    Position 1–N: all flare-friendly meals (best first)
    Position N+1+: all other meals (best first)
    
    Add to every flare-friendly meal explanation:
    "Recommended first because you are in flare mode
     — this meal is gentle, low effort, and
     anti-inflammatory."

STEP 5 — Apply nutrition gap boosting (Priority 4)
  Get NutritionGaps from nutrition_tracker
  Adjust meal scores based on gaps:

  if is_protein_low:
    meals with total_protein_g >= 25 → score +1.0
  if is_fiber_low:
    meals with total_fiber_g >= 8 → score +1.0
  if is_omega3_low:
    meals with total_omega3_g >= 0.5 → score +1.5
  if is_sugar_over:
    meals with total_sugar_g <= 5 → score +1.0
    meals with total_sugar_g >= 15 → score -2.0
  if is_sodium_over:
    meals with total_sodium_mg <= 300 → score +1.0
    meals with total_sodium_mg >= 600 → score -1.5

  After adjustment clamp all scores 0–10

STEP 6 — Apply preference filter (Priority 5)
  Load user preferences from core.user_preferences
  If user is vegetarian:
    remove non-vegetarian meals
  If user has cuisine preference:
    boost matching cuisine meals by +0.5
  If user has budget_friendly flag:
    boost budget_friendly tagged meals by +0.5

STEP 7 — Apply variety penalty (Priority 7)
  Load recommendation_logs for last 7 days
  For each candidate meal:
    if meal was recommended in last 3 days:
      score -= 1.5
    if meal category same as last 2 meals:
      score -= 0.5
  After penalty clamp all scores 0–10

STEP 8 — Final ranking
  Sort remaining candidates by adjusted score DESC
  Take top 5:
    index 0 → primary_recommendation
    index 1–4 → alternatives

STEP 9 — Generate explanation text
  Build human-readable explanation for primary meal:

  Examples:
  "Grilled salmon with brown rice recommended because:
   your omega-3 intake today is low, salmon is your
   top anti-inflammatory food, and it has not been
   suggested recently."

  "Lentil soup recommended because: you are in flare
   mode — this is a gentle, easy-to-prepare meal with
   strong anti-inflammatory properties."

  "Oat porridge with blueberries recommended because:
   your fiber intake today is low and this meal
   provides 8g of dietary fiber."

  Explanation must reference:
  - the dominant rule that drove the recommendation
  - one specific nutrient benefit if applicable
  - flare mode if active

STEP 10 — Save to recommendation_logs
  Insert into intelligence.recommendation_logs:
    user_id
    meal_id (primary recommendation)
    explanation_text
    rule_priority_applied (dominant rule)
    flare_mode_active
    alternatives_json (list of alternative meal IDs)
    daily_nutrition_context_json (snapshot of gaps)
    feedback_status: pending
    shown_at: now()
